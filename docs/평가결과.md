## 2. 처음 평가에서 틀린 질문과 원인

**q18 "II급 비밀이 뭐야"**: 모델을 부르기도 전에 보안 장치가 막았습니다.

- 원인은 프롬프트·검색·채점 기준이 아니라 **보안 장치의 오판**입니다.
- 용어의 뜻만 묻는 질문인데, 'II급 비밀'이라는 글자를 비밀 표기로 보았습니다.

## 3. 고친 것

### 보안 장치 (`security/classification.py`)

- **우회 구멍을 막았습니다.** 영문 표기 뒤에 조사가 붙으면 차단되지 않았습니다(예: 'SECRET이라고', 'CONFIDENTIAL로', 'FOUO인').
- 소문자 로마숫자 'ⅱ급'이 III급으로 낮게 판정되던 것을 고쳤습니다.
- 'S//NF', 'C//' 같은 배너 표기를 탐지합니다.
- 다음과 같은 뜻 묻는 질문은 막지 않습니다: 'II급 비밀이 뭐야', '군사기밀이란?', 'TOP SECRET이 뭐야?', '군사기밀보호법 위반하면?'.
  - 입력 **전체**가 용어와 질문으로만 되어 있을 때만 통과시킵니다. 그래서 뒤에 문서 내용을 붙여 빠져나갈 수는 없습니다.
- 공백 2만 자를 넣으면 검사에 약 10초가 걸려 서버가 멈추던 문제를 고쳤습니다.

### 의무후송 요청(9-Line MEDEVAC) 양식 (`tools/reports.py`, 샘플 문서)

- 7번(착륙 지점 표시)의 B와 C가 뒤바뀌어 있었습니다. 표준은 A 패널, B 발광 신호, C 연막, D 없음, E 기타입니다.
- 4번 B는 '들것걸이'가 아니라 '호이스트(인양기)'가 맞습니다.
- 모델이 틀린 양식을 답변에 그대로 옮기고 있었습니다. 답변을 문서와 한 줄씩 대조하다가 찾았습니다.

### 답변 방식 (`prompts.py`)

- 출처 번호 [n] 은 검색 결과가 그 문장을 직접 뒷받침할 때만 답니다.
- '지식 베이스에 없다'고 말하기 전에 다른 검색어로 한 번 더 찾습니다.
- 반복되는 맺음말과 묻지 않은 절차 덧붙이기를 줄였습니다.
- 효과: 통과율은 그대로이고 출력 토큰 −29%, 응답 시간 −31%.

### 평가와 운영

- **토큰 집계**: 캐시에서 읽은 입력과 캐시에 새로 쓴 입력이 빠져 있어, 실제 사용량이 약 1/6 로 보였습니다. 이제 평가 보고서·감사 로그·CLI 에 함께 표시합니다.
- **질문셋**: 22개에서 37개로 늘렸습니다. 추가한 질문은 다음을 다룹니다.
  - 보안 장치 우회 시도
  - 지식 베이스 밖 질문
  - 폭발물 제조 요청 거절
  - 암구호
  - 마스킹 값 누출
  - AI 속이기(시스템 프롬프트 유출 시도)
  - 도구 계산
- **자동 검사(CI)**: GitHub Actions 를 추가했습니다. 코드를 올릴 때마다 Python 3.10/3.12/3.13 에서 테스트가 돕니다.

## 5. 결정이 필요한 사항 (아직 바꾸지 않음)

1. **보안 장치를 얼마나 엄격하게 둘지**
   - '비밀문서', '비밀 자료', '비밀취급' 같은 일반 단어만 있어도 막습니다.
   - 그래서 「비밀 보관 및 폐기」 섹션에 대한 평범한 질문 12개 중 10개가 막힙니다(예: '비밀문서 보관 방법 알려줘').
2. **모델 선택**
   - 비용을 줄이려면 Sonnet 5.5 가 정확도를 유지하는 후보입니다.
   - Haiku 는 권하지 않습니다.
3. **안전 정책 거절 안내문**
   - 영문 정책 설명과 지원 사이트 주소가 사용자에게 그대로 보입니다(`assistant.py` 의 거절 처리 부분).

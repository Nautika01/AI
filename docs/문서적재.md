# 문서 적재 가이드: 실제 규정·교범을 지식 베이스에 넣기

비서가 아는 내용은 `data/docs/` 안의 Markdown 문서가 전부입니다. 이 문서는 HWP·PDF 같은 원본 파일을 그 형식으로 바꾸고, 검색이 잘 되게 다듬는 방법을 설명합니다.

> ⚠️ 비밀·대외비 표기가 있는 자료는 넣지 마십시오. 이 비서는 일반(평문) 자료용입니다.

---

## 1. 변환: `defense-ai ingest`

지원 형식: **HWP(한글 5.0), HWPX, DOCX, PDF, TXT, MD**. 변환은 전부 PC 안에서 이루어지며 외부 서비스로 나가지 않습니다.

```powershell
# 미리보기 (저장하지 않고 제목·섹션 구조만 확인)
defense-ai ingest 경계근무규정.hwp --dry-run

# 변환해서 data\docs\ 에 저장
defense-ai ingest 경계근무규정.hwp --category 규정 --effective-date 2025-03-01

# 폴더째로 (하위 폴더 포함, 지원 형식만 골라서)
defense-ai ingest C:\자료\규정집 --category 규정
defense-ai ingest C:\자료\교범 --category 교범 --tags 전술,훈련
```

결과 예시:

```
✔ 경계근무규정.hwp (hwp, 문단 212개, 섹션 38개, 조문) → data\docs\경계근무규정.md
완료: 변환 1개, 건너뜀 0개, 실패 0개
```

| 옵션 | 설명 |
|---|---|
| `--category` | 문서 분류. 검색 범위를 좁힐 때 쓰입니다(규정 / 교범 / 지침 등 자유) |
| `--effective-date` | 시행일. 검색 결과에 함께 표시됩니다 |
| `--version` / `--tags` | 버전, 태그(쉼표 구분) |
| `--title` | 제목을 직접 지정 (파일 1개일 때) |
| `--out` | 출력 폴더 (기본 `data/docs`) |
| `--overwrite` | 같은 이름의 .md 가 있으면 덮어쓰기 |
| `--dry-run` | 저장 없이 구조만 보기 |

### 구조를 어떻게 잡는가

| 문서 종류 | 감지 기준 | 섹션 단위 |
|---|---|---|
| 규정류 | `제N조` 가 2개 이상 | 조문. 장·절 제목이 앞에 붙어 `제2장 근무 편성 › 제3조(근무 형태)` 처럼 표시 |
| 교범·지침류 | `1.` `2.1` 같은 번호 제목이 2개 이상 | 번호 제목 |
| 그 외 | – | 문단만 (긴 문서는 자동 분할) |

표는 `| 셀 | 셀 |` 한 줄로 바뀌어 검색됩니다. 그림·수식·각주·머리말·꼬리말은 버립니다.

- 장 제목은 `제1장 총칙` 처럼 "제N장" 뒤에 띄어쓰기가 있어야 인식됩니다(`제3장비 점검` 같은 본문 문장을 장 제목으로 오인하지 않기 위함).
- `제3조의2(특례)` 같은 가지 조문은 섹션명에 `의2` 까지 그대로 남습니다. `제5조에 따라 …` 처럼 조문을 인용하는 본문 문장은 새 조문으로 나뉘지 않습니다.
- PDF 의 쪽 번호는 각 쪽의 첫 줄·마지막 줄에 있는 숫자만 지웁니다. 표 안의 숫자 줄은 보존됩니다.
- 이미 변환한 `.md` 를 다시 넣으면 머리말(front matter)을 읽어 그대로 이어받습니다.

### 변환 후 꼭 할 일

1. 생성된 `.md` 를 열어 **제목과 섹션 제목이 맞는지** 봅니다. 첫 줄이 제목으로 잘못 잡혔으면 `--title` 로 다시 변환하거나 직접 고칩니다.
2. 맨 위 머리말(front matter)의 `effective_date`, `version` 을 채웁니다.
3. 비서를 재시작합니다. 다시 색인되면서 임베딩이 계산되고 `storage/index/` 에 캐시됩니다.

### 변환이 안 될 때

| 메시지 | 조치 |
|---|---|
| `HWP 5.0 형식이 아닙니다` | 한글 3.0 이하 구형 파일. 한글에서 HWPX 또는 PDF 로 다시 저장 |
| `암호가 걸린 … 파일` | 암호 해제 후 다시 시도 |
| `배포용(DRM) HWP` | 본문 추출 불가. 작성자에게 일반 파일 요청 |
| `PDF 에서 글자를 찾지 못했습니다` | 스캔 이미지 PDF. OCR 로 글자를 추출한 뒤 TXT 로 변환 |
| 섹션이 하나도 안 잡힘 | 조문·번호 제목이 없는 문서. 직접 `## 소제목` 을 넣어 주면 검색 품질이 좋아짐 |

HWP 변환은 표준 규격을 바탕으로 구현했으나 실제 파일은 버전·작성 방식이 다양합니다. 결과가 이상하면 한글에서 HWPX 로 저장해 다시 변환하는 것이 가장 확실합니다.

## 2. 머리말(front matter) 메타데이터

Markdown 맨 위에 두는 정보입니다. 직접 쓴 문서에도 붙일 수 있습니다.

```
---
title: 경계근무 규정
category: 규정
effective_date: 2025-03-01
version: 3.1
source_file: 경계근무규정.hwp
tags: 경계, 근무
---
```

- `category` 로 검색 범위를 좁힐 수 있습니다: `defense-ai search "교대" --category 규정`. 비서도 필요하면 분류를 지정해 검색합니다.
- `effective_date`, `version` 은 검색 결과에 표시되어 어느 판본인지 알 수 있게 합니다.
- 알 수 없는 항목(예: `unit: 1사단`)도 그대로 보존됩니다.

## 3. 동의어 사전: `data/synonyms.json`

"보초"라고 물었는데 문서에는 "경계근무"라고만 쓰여 있으면 못 찾습니다. 이런 짝을 적어 두면 질문에 자동으로 보태집니다. 모델 없이 검색을 개선하는 가장 싸고 확실한 방법입니다.

```json
{
  "경계근무": ["보초", "불침번", "경계 근무"],
  "MEDEVAC": ["의무후송", "환자후송", "메데박", "9라인"]
}
```

키와 값은 서로 동의어 그룹이 됩니다. 부대에서 쓰는 은어·약칭·옛 명칭을 여기에 쌓아 두십시오. 평가(`defense-ai eval`)에서 검색을 놓친 질문을 보면 무엇을 추가해야 할지 바로 보입니다.

## 4. 의미 기반 검색(임베딩)

기본 설정은 모델 없이 동작하는 어휘 검색 + 문자 해시 벡터입니다. 문서가 수백 편으로 늘고 동의어 사전으로도 부족하면 **임베딩 모델**을 붙입니다. 망 분리 환경에서는 Ollama 가 제공하는 임베딩 모델을 쓰면 됩니다.

```powershell
ollama pull bge-m3            # 다국어(한국어 포함) 임베딩, 약 1.2GB. 또는 nomic-embed-text
```

`.env`:
```
DAI_EMBEDDINGS=openai
DAI_EMBEDDINGS_BASE_URL=http://127.0.0.1:11434/v1
DAI_EMBEDDINGS_MODEL=bge-m3
```

- 검색은 어휘 점수와 벡터 점수를 합쳐 순위를 매깁니다(하이브리드). 어휘가 전혀 안 겹쳐도 뜻이 비슷하면 올라옵니다.
- 임베딩은 문서 청크마다 한 번만 계산되고 `storage/index/` 에 캐시됩니다. 문서가 바뀐 부분만 다시 계산합니다.
- 임베딩 서버가 꺼져 있으면 비서는 멈추지 않고 어휘 검색만으로 동작하며, 로그에 사유를 남깁니다.
- `DAI_EMBEDDINGS=off` 로 두면 BM25 어휘 검색만 씁니다.

| 설정 | 기본값 | 설명 |
|---|---|---|
| `DAI_EMBEDDINGS` | `hash` | `hash`(모델 불필요) / `openai`(임베딩 서버) / `off` |
| `DAI_EMBEDDINGS_BASE_URL` | `DAI_LOCAL_BASE_URL` 과 동일 | 임베딩 서버 주소 |
| `DAI_EMBEDDINGS_MODEL` | `nomic-embed-text` | 임베딩 모델 이름 |
| `DAI_SYNONYMS_PATH` | `data/synonyms.json` | 동의어 사전 |
| `DAI_INDEX_CACHE_DIR` | `storage/index` | 임베딩 캐시 폴더 |

## 5. 권장 순서

1. 문서 10~20편을 변환해 넣고 `defense-ai eval` 로 검색 적중률을 봅니다.
2. 놓친 질문을 보고 동의어를 추가하거나 문서의 섹션 제목을 손봅니다.
3. 문서가 100편을 넘기 시작하면 임베딩 모델을 붙이고 다시 평가해 비교합니다.
4. 평가 결과 JSON 을 보관해 두고, 문서·설정을 바꿀 때마다 `--compare` 로 퇴보가 없는지 확인합니다.

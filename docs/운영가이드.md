# 운영 가이드: 여러 사람이 쓰는 서버로 띄우기

`defense-ai serve` 로 실행하면 아이디·비밀번호로 로그인하는 웹 채팅 서비스가 됩니다. 사용자마다 대화 기록이 분리 저장되고, 관리자가 계정과 비밀취급인가 등급을 관리합니다.

---

## 1. 구성 요소

| 구성 | 위치 | 설명 |
|---|---|---|
| 웹 UI | `http://서버주소:8000/` | 브라우저 채팅 화면 (로그인, 대화 목록, 스트리밍 응답) |
| HTTP API | `http://서버주소:8000/docs` | 자동 생성된 API 문서 (Swagger) |
| 사용자·토큰·대화 DB | `storage/defense.db` | SQLite 단일 파일. 외부 DB 서버 불필요 |
| 감사 로그 | `audit/audit.jsonl` | 모든 질문·차단·오류 기록 (원문 대신 해시) |
| 지식 베이스 | `data/docs/` | Markdown 문서. 재시작 시 자동 색인 |

## 2. 처음 띄우기 (서버 1대 기준)

### 2-1. 관리자 계정 만들기

서버를 실행하기 전에 관리자 계정이 하나는 있어야 합니다.

```powershell
defense-ai users add admin --role admin
```

비밀번호를 두 번 물어봅니다(8자 이상). 화면에 표시되지 않으니 그대로 입력하고 Enter.

### 2-2. 실행

```powershell
defense-ai serve --host 0.0.0.0 --port 8000
```

- `--host 0.0.0.0` : 같은 네트워크의 다른 PC에서 접속 허용. 본인 PC에서만 쓰려면 `127.0.0.1`
- 브라우저에서 `http://서버IP:8000` 접속 → 관리자 계정으로 로그인

### 2-3. 사용자 추가

```powershell
defense-ai users add kim                         # 일반 사용자, 인가 등급 대외비(기본)
defense-ai users add lee --clearance UNCLASSIFIED  # 일반 자료만 허용
defense-ai users add park --role admin           # 관리자 추가
defense-ai users list
```

인가 등급(`--clearance`)은 `UNCLASSIFIED`(일반) `RESTRICTED`(대외비) `CONFIDENTIAL`(III급) `SECRET`(II급) `TOP_SECRET`(I급) 중 하나입니다. 단, 서버 전역 설정 `DAI_MAX_CLASSIFICATION`(기본 대외비)이 상한이므로 그보다 높은 등급을 줘도 전역 설정까지만 허용됩니다.

그 밖의 명령:

```powershell
defense-ai users passwd kim          # 비밀번호 변경 (기존 로그인 전부 무효화)
defense-ai users set kim --clearance UNCLASSIFIED --role user
defense-ai users disable kim         # 로그인 차단
defense-ai users enable kim
defense-ai users remove kim          # 계정과 대화 기록 삭제
```

관리자는 웹 API(`/admin/users`)로도 같은 작업을 할 수 있습니다.

## 3. Docker 로 띄우기

Docker가 설치된 서버라면 두 줄이면 됩니다.

```bash
cp .env.example .env            # ANTHROPIC_API_KEY 와 DAI_ADMIN_PASSWORD 를 채운다
docker compose up -d --build
```

- `DAI_ADMIN_PASSWORD` 는 **사용자가 한 명도 없을 때 한 번만** `admin` 계정을 만드는 데 쓰입니다. 첫 기동 후 `.env` 에서 지우십시오.
- `data/docs`, `storage`, `audit` 폴더가 컨테이너 밖에 남으므로 컨테이너를 지워도 데이터가 보존됩니다.
- 로그: `docker compose logs -f`, 중지: `docker compose down`

## 4. 보안 체크리스트

실제 부대망에 올리기 전에 확인하십시오.

- [ ] **HTTPS**: 서버 앞에 Nginx·Caddy 같은 리버스 프록시를 두고 TLS를 종단합니다. 토큰이 평문 HTTP로 오가면 안 됩니다.
- [ ] **방화벽**: 8000 포트는 프록시에서만 접근하도록 제한합니다.
- [ ] **관리자 비밀번호**: 초기 `DAI_ADMIN_PASSWORD` 는 사용 후 제거하고, 관리자 계정 비밀번호를 변경합니다.
- [ ] **토큰 유효 시간**: `DAI_TOKEN_TTL_HOURS`(기본 12시간)를 근무 형태에 맞게 조정합니다.
- [ ] **감사 로그 보관**: `audit/audit.jsonl` 을 주기적으로 보안 저장소로 옮기고 접근을 제한합니다. 관리자는 `/admin/audit` 로도 조회할 수 있습니다.
- [ ] **지식 베이스 검토**: `data/docs/` 에 비밀·대외비 표기 자료가 없는지 확인합니다.
- [ ] **백업**: `storage/defense.db` 를 정기 백업합니다 (SQLite 파일 복사).
- [ ] **사용자 교육**: 표기 없는 비밀 내용은 기술적으로 걸러지지 않음을 공지합니다.

## 5. 동작 방식 요약

1. 로그인하면 12시간짜리 토큰을 받고, 이후 요청은 `Authorization: Bearer <토큰>` 헤더로 인증합니다. DB에는 토큰 해시만 저장됩니다.
2. 로그인에 5회 연속 실패하면 10분간 잠깁니다 (`DAI_LOGIN_MAX_ATTEMPTS`, `DAI_LOGIN_LOCKOUT_MINUTES`).
3. 질문은 사용자 인가 등급과 전역 허용 등급 중 **낮은 쪽**을 기준으로 비밀 표기를 검사합니다.
4. 대화 기록은 마스킹된 상태로 저장되므로 군번·전화번호 원문은 DB에 남지 않습니다.
5. 한 대화에 동시에 두 요청이 들어오면 두 번째는 409로 거절됩니다.
6. 비밀번호 변경·계정 비활성화 시 그 사용자의 로그인은 즉시 무효화됩니다.

## 6. 환경 변수 (서버 전용)

| 변수 | 기본값 | 설명 |
|---|---|---|
| `DAI_DB_PATH` | `storage/defense.db` | 사용자·토큰·대화 DB 파일 |
| `DAI_TOKEN_TTL_HOURS` | `12` | 로그인 토큰 유효 시간 |
| `DAI_LOGIN_MAX_ATTEMPTS` | `5` | 잠금 전 허용 실패 횟수 |
| `DAI_LOGIN_LOCKOUT_MINUTES` | `10` | 잠금 시간 |
| `DAI_CORS_ORIGINS` | (없음) | 웹 UI를 다른 도메인에 둘 때 허용 출처 (쉼표 구분) |
| `DAI_ADMIN_PASSWORD` | (없음) | 최초 기동 시 admin 자동 생성용. 사용 후 제거 |

모델·보안 관련 변수는 `README.md` 를 참고하십시오.

## 7. 자주 묻는 문제

| 증상 | 조치 |
|---|---|
| `등록된 사용자가 없습니다` 로 서버가 안 뜸 | `defense-ai users add admin --role admin` 먼저 실행 |
| 로그인하면 "잠시 잠겼습니다" | 10분 뒤 재시도. 급하면 서버 재시작(잠금은 메모리에만 있음) |
| 다른 PC에서 접속이 안 됨 | `--host 0.0.0.0` 으로 실행했는지, 방화벽이 8000 포트를 막는지 확인 |
| 대화가 사라짐 | `DAI_DB_PATH` 가 바뀌었거나 `storage/` 폴더가 삭제됨. 백업에서 복원 |
| `409 이미 처리 중` | 같은 대화에 응답이 끝나기 전에 다시 보낸 것. 응답 완료 후 재전송 |

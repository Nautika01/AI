# 로컬 모델로 운용하기 (망 분리 환경)

외부 서버(Anthropic API)로 아무것도 보내지 않고, 부대 서버나 PC 안에서 모델을 직접 돌리는 방식입니다. `.env` 의 `DAI_BACKEND=local` 한 줄로 전환되며, 비밀 등급 차단·마스킹·감사 로그·문서 검색·로그인·웹 화면은 그대로 동작합니다.

> ⚠️ 로컬 모델은 Claude보다 답변 품질과 추론력이 낮습니다. 모델 크기(7B 이하 / 14B / 30B 이상)에 따라 차이가 크므로, 실제 질문으로 비교해 보고 결정하십시오.

---

## 1. 동작 방식

| 항목 | Claude 모드 | 로컬 모드 |
|---|---|---|
| 모델 위치 | Anthropic 서버 | 부대 서버·PC (Ollama, vLLM, llama.cpp 등) |
| 데이터 외부 전송 | 마스킹 후 전송 | **없음** |
| 문서 검색 | 모델이 필요할 때 도구로 호출 | **매 질문마다 자동 검색** 후 참고 문서를 질문에 첨부 |
| 도구(시간 변환 등) | 항상 사용 | 모델 서버가 함수 호출을 지원하면 사용, 아니면 자동으로 끔 |
| 필요 장비 | 없음 | GPU 권장 (작은 모델은 CPU 가능) |

작은 모델은 "지금 검색이 필요한가"를 스스로 판단하는 데 서툴기 때문에, 로컬 모드는 질문이 들어오면 무조건 지식 베이스를 먼저 검색해서 상위 문서(`DAI_LOCAL_RAG_TOP_K`, 기본 4개)를 질문 뒤에 붙여 줍니다. 모델은 그 문서를 근거로 [번호]를 달아 답합니다.

---

## 2. 모델 서버 준비

가장 쉬운 것은 **Ollama** 입니다. Windows·Mac·Linux 모두 지원하고 설치 후 명령 한 줄로 모델을 받습니다.

### 2-1. Ollama 설치와 모델 받기

1. [ollama.com/download](https://ollama.com/download) 에서 설치
2. PowerShell 에서 모델 받기 (처음 한 번, 수 GB 다운로드):

```powershell
ollama pull qwen2.5:7b          # 범용, 한국어 양호, 함수 호출 지원 (약 4.7GB)
ollama pull exaone3.5:7.8b      # LG AI연구원, 한국어 특화 (약 4.8GB)
ollama pull qwen2.5:1.5b        # 아주 작음, GPU 없이 시험용 (약 1GB)
```

3. 받은 모델 확인: `ollama list`

Ollama는 설치 후 백그라운드에서 `http://127.0.0.1:11434` 로 대기합니다. 다른 PC에서 접속하게 하려면 환경 변수 `OLLAMA_HOST=0.0.0.0` 을 설정하고 재시작합니다.

### 2-2. 어떤 모델을 고를지

| 장비 | 권장 모델 | 비고 |
|---|---|---|
| GPU 없음, RAM 8GB | `qwen2.5:1.5b` | 시험용. 느리고 품질 낮음 |
| GPU 8GB (RTX 3060 등) | `qwen2.5:7b`, `exaone3.5:7.8b` | 실사용 최소선 |
| GPU 16~24GB | `qwen2.5:14b`, `exaone3.5:32b`(양자화) | 권장 |
| GPU 48GB 이상 / 서버 | `qwen2.5:32b` 이상, vLLM 운용 | 다중 사용자 |

### 2-3. 다른 모델 서버

vLLM, llama.cpp(`llama-server`), LM Studio 도 같은 규격(`/v1/chat/completions`)을 제공하므로 `DAI_LOCAL_BASE_URL` 만 바꾸면 됩니다.

```
vLLM:         DAI_LOCAL_BASE_URL=http://서버IP:8000/v1   DAI_LOCAL_MODEL=<서빙 모델명>  DAI_LOCAL_API_KEY=<--api-key 값>
llama-server: DAI_LOCAL_BASE_URL=http://서버IP:8080/v1   DAI_LOCAL_MODEL=<아무 이름>
LM Studio:    DAI_LOCAL_BASE_URL=http://127.0.0.1:1234/v1
```

---

## 3. 비서 설정

`.env` 에서 아래 세 줄을 고칩니다.

```
DAI_BACKEND=local
DAI_LOCAL_BASE_URL=http://127.0.0.1:11434/v1
DAI_LOCAL_MODEL=qwen2.5:7b
```

`ANTHROPIC_API_KEY` 는 비워 두어도 됩니다. 로컬 모드에서는 쓰지 않습니다.

---

## 4. 점검

```powershell
defense-ai local-check
```

세 단계를 차례로 확인합니다.

```
[1/3] 서버 연결: http://127.0.0.1:11434/v1
  ✔ 연결됨. 서버의 모델 2개: qwen2.5:7b, exaone3.5:7.8b
[2/3] 모델 확인: qwen2.5:7b
  ✔ 모델 있음
[3/3] 응답 시험: '경계 근무 교대 시 보고 형식은?'
  ✔ 응답 수신 (312자, 도구 ['search_defense_docs'], 함수 호출 지원: 예)
  ▶ 경계 근무 교대 보고는 "근무자, 구역, 시각, 특이사항 유무"를 포함합니다 [1] …
점검 완료. .env 에 DAI_BACKEND=local 을 설정하면 이 모델로 동작합니다.
```

✖ 가 나오면 메시지가 원인을 알려 줍니다(서버 미실행, 모델 미설치, 응답 시간 초과 등).

점검이 끝나면 평소처럼 `defense-ai` 또는 `defense-ai serve` 로 실행합니다. 배너의 모델 이름이 `local:qwen2.5:7b` 처럼 바뀝니다.

## 5. 설정 항목

| 변수 | 기본값 | 설명 |
|---|---|---|
| `DAI_BACKEND` | `claude` | `local` 로 바꾸면 로컬 모드 |
| `DAI_LOCAL_BASE_URL` | `http://127.0.0.1:11434/v1` | 모델 서버 주소 (`/v1` 까지) |
| `DAI_LOCAL_MODEL` | `qwen2.5:7b` | 모델 이름 |
| `DAI_LOCAL_API_KEY` | (없음) | 서버가 인증을 요구할 때만 |
| `DAI_LOCAL_TOOLS` | `auto` | 함수 호출 사용. `off` 면 검색 주입만 사용 |
| `DAI_LOCAL_RAG_TOP_K` | `4` | 질문에 붙이는 참고 문서 수. `0` 이면 검색 주입을 끔 |
| `DAI_LOCAL_TIMEOUT` | `300` | 응답 대기 시간(초). CPU 모델은 늘려야 할 수 있음 |
| `DAI_LOCAL_TEMPERATURE` | `0.2` | 생성 온도. 낮을수록 보수적 |
| `DAI_LOCAL_NUM_CTX` | (비움 → 4096) | 모델 서버의 컨텍스트 길이. vLLM `--max-model-len`, llama-server `-c`, Ollama `OLLAMA_CONTEXT_LENGTH` 와 같게 |
| `DAI_LOCAL_MAX_TOKENS` | (비움 → 자동) | 로컬 응답 최대 토큰 |
| `DAI_MAX_TOKENS` | `16000` | 응답 최대 길이 (양쪽 공통) |

---

### 컨텍스트 길이 맞추기

로컬 모델은 한 번에 읽을 수 있는 길이(컨텍스트)가 정해져 있습니다. 비서는 `DAI_LOCAL_NUM_CTX` 안에 시스템 지침·참고 문서·대화 이력·답변 자리가 모두 들어가도록 **오래된 대화부터 자동으로 정리**하고, 질문 자체가 너무 길면 보내지 않고 안내합니다. 이 값이 실제 서버 설정보다 크면 서버가 앞부분(보안 지침)을 잘라 버릴 수 있으므로 반드시 서버와 같게 맞추십시오. `defense-ai local-check` 가 현재 가정한 값을 보여 줍니다.

Ollama 에서 기본(4096)보다 길게 쓰려면 서버를 `OLLAMA_CONTEXT_LENGTH=16384` 로 띄우고 `.env` 에 `DAI_LOCAL_NUM_CTX=16384` 를 함께 적습니다.

## 6. 품질을 올리는 방법 (순서대로)

1. **모델 크기 키우기**: 7B → 14B → 32B. 가장 확실한 방법입니다.
2. **참고 문서 다듬기**: 질문에 자주 나오는 내용이 짧고 명확한 섹션으로 정리돼 있으면 작은 모델도 잘 답합니다.
3. **`DAI_LOCAL_RAG_TOP_K` 조정**: 작은 모델은 2~3개가 오히려 나을 수 있습니다(문서가 많으면 헷갈림).
4. **미세조정(LoRA)**: 부대 문서·문답 데이터로 모델을 추가 학습. GPU 1장으로 수 시간이면 가능하며, 필요 시 학습 절차를 별도로 안내합니다.

---

## 7. 한계

- 로컬 모델은 안전 분류기나 서버측 폴백이 없으므로 시스템 프롬프트의 지침에만 의존합니다. 사용자 교육과 감사 로그 검토가 더 중요해집니다.
- 함수 호출 품질이 낮은 모델은 도구 인자를 잘못 만들 수 있습니다. 그 경우 오류가 모델에게 되돌아가 다시 시도하지만, 반복되면 `DAI_LOCAL_TOOLS=off` 로 두는 편이 안정적입니다.
- 이 저장소의 로컬 백엔드는 표준 규격을 흉내 낸 시험 서버로 검증되었습니다. 실제 모델 서버에서는 `defense-ai local-check` 로 꼭 확인하십시오.
